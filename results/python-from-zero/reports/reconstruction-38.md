# 38. Итоговый проект: учёт расходов

После урока вы сможете: Самостоятельно собрать программу из контракта, функций и проверяемых частей.

Нужные знания: Списки, функции, максимум, денежные суммы в int

## От задачи к способу решения

Здесь нужно соединить несколько известных решений, поэтому начните с контракта. Суммы приходят в копейках и остаются int до конца. Остаток может быть отрицательным: это означает перерасход. Среди равных самых дорогих покупок выбираем первую по порядку ввода. Для пустого списка третья строка целиком равна НЕТ ПОКУПОК, без префикса ПОКУПКА.

Дополнительный пример пустого списка. Вход:

```text
505
0
```

Вывод:

```text
ИТОГО 0.00
ОСТАТОК 5.05
НЕТ ПОКУПОК
```

Сквозной пример: бюджет 100000 копеек, покупки хлеб за 12550, транспорт за 15000, тетрадь за 7050. Расходы 34600 копеек, остаток 65400. Самая дорогая покупка — транспорт. В рублях это 346.00 и 654.00. Название нужно сохранить вместе с ценой, иначе после поиска максимума не узнаем, к чему он относится.

**Запись покупки** представим маленьким списком из двух элементов: `[name, amount]`. Нулевой элемент — название, первый — стоимость. purchases — список таких записей. `purchases[index][1]` сначала выбирает покупку по index, затем её стоимость по внутреннему индексу 1. Это два последовательных обращения, а не двумерная арифметика. Каждая новая пара создаётся отдельным выражением в цикле.

План состоит из четырёх частей. Прочитать и сохранить покупки. Одним проходом сложить их цены. Найти индекс максимальной цены, заменяя кандидата только при строгом превосходстве. Оформить денежные значения и вывести три строки. Нет нужды сортировать покупки: нам нужен максимум и правило первого появления, а не новый порядок всех записей.

Функция money_text получает целые копейки и возвращает точную запись. Сначала отдельно сохраняет знак, затем работает с abs. Рубли — value // 100, копейки — value % 100. Формат `:02d` означает целую запись минимум в две позиции с ведущими нулями: 5 копеек покажутся как 05. Мы не делим на 100 через / и не переводим суммы в float.

Функция largest_purchase_index возвращает индекс или −1 для пустого списка. В непустом списке первым кандидатом становится индекс 0. Если новая цена равна лучшей, не обновляем индекс: так сохраняется самая ранняя покупка. Основная часть обязана проверить −1 до получения названия, иначе отрицательный индекс случайно обратился бы к последнему элементу.

Напишите эти функции сначала отдельно. Проверьте money_text на 0, 5, 100, −5 и −105. Затем проверьте максимум на пустом списке, одной записи и двух равных ценах. После этого соединяйте ввод и вывод. Так сложность проекта становится несколькими небольшими проверяемыми задачами.

Для самостоятельной защиты закройте реализацию и объясните: почему суммы точны, зачем хранятся пары, почему не нужна сортировка, почему используется строгое >, что происходит при перерасходе и почему пустой список нельзя индексировать. Если можете написать новый вариант по этим ответам, вы владеете основами, а не только узнаёте знакомый код.

## Задача и формат данных

Получить бюджет и покупки; вывести сумму расходов, остаток и название первой самой дорогой покупки.

**Ввод:** Бюджет в копейках, затем n отдельной строкой; далее n пар строк: название покупки, стоимость в копейках.

**Вывод:** Три строки. Первая: ИТОГО и сумма в рублях с копейками. Вторая: ОСТАТОК и разность бюджета и расходов. При n > 0 третья строка: ПОКУПКА и название первой самой дорогой покупки. При n = 0 третья строка содержит только НЕТ ПОКУПОК, без слова ПОКУПКА.

**Допустимые данные:** 0 <= budget <= 1000000000; 0 <= n <= 1000; стоимость от 0 до 1000000; название от 1 до 100 символов. Перерасход допускается.

Вход сквозного примера:

```text
100000
3
хлеб
12550
транспорт
15000
тетрадь
7050
```

Ожидаемый вывод:

```text
ИТОГО 346.00
ОСТАТОК 654.00
ПОКУПКА транспорт
```

## Пройдём пример руками

| Шаг | Действие и причина | Состояние или результат |

## Почему работает и сколько действий требуется

Сумма учитывает каждую цену ровно раз. Поиск максимума поддерживает лучший индекс обработанной части и не заменяет его при равенстве. Форматирование модуля суммы разделяет его на рубли и остаток, затем восстанавливает знак. Все циклы конечны по n. Работа линейна по числу записей плюс общая длина названий; память хранит все записи и названия, тоже линейна.

## Границы и частые ошибки

Файлы и постоянное сохранение данных здесь ещё не изучены: после окончания программы покупки не сохраняются на диск. Их добавление требует следующей темы про файлы. Для неверных цен сначала нужно согласовать правило отказа и повторного ввода.
