# Проверка урока 38

Авторская самопроверка, не эксперимент с реальным студентом. Исходные знания: Списки, функции, максимум, денежные суммы в int

| Проверка | Конкретное свидетельство в финальном тексте |
| --- | --- |
| Постановка | Получить бюджет и покупки; вывести сумму расходов, остаток и название первой самой дорогой покупки. |
| Понятия | В разделе «От задачи к способу решения» новые операции объяснены до полной реализации; исходные знания перечислены перед разделом. |
| Выбор метода | Самостоятельно собрать программу из контракта, функций и проверяемых частей. |
| Сквозной пример | Первый пример main: Все части проекта. Те же данные находятся в таблице и проверяемом описании. |
| Ручной проход | Таблица «Пройдём пример руками»: Вычесть расходы из бюджета и оформить целые копейки; результат: ИТОГО 346.00, ОСТАТОК 654.00, ПОКУПКА транспорт |
| Реализация | Полная программа дословно совпадает с code/PYTHON311/main.py; содержит все чтения и вывод по контракту. |
| Разбор | Ввод и вывод находятся в основной части, функции получают готовые данные. total хранит точную сумму копеек. money_text отдельно оформляет знак, чтобы отрицательный остаток не разбивался на несогласованные рубли и копейки из-за округления // вниз. largest_purchase_index не меняет записи и возвращает лишь позицию. |
| Корректность | Сумма учитывает каждую цену ровно раз. Поиск максимума поддерживает лучший индекс обработанной части и не заменяет его при равенстве. Форматирование модуля суммы разделяет его на рубли и остаток, затем восстанавливает знак. Все циклы конечны по n. Работа линейна по числу записей плюс общая длина названий; память хранит все записи и названия, тоже линейна. |
| Сложность | В «Почему работает и сколько действий требуется» оценка связана с количеством проходов и фактически хранимыми данными. |
| Практика | Вопросы 1–2 проверяют механизм и причину; задачи 3–4 требуют реализации и изменения условия. Решения отделены. |
| Языковая версия | Только Python, синтаксис совместим с Python 3.11. Фактический интерпретатор указан в verification.json, совместимость не выдается за запуск 3.11. |

Ограничения: Файлы и постоянное сохранение данных здесь ещё не изучены: после окончания программы покупки не сохраняются на диск. Их добавление требует следующей темы про файлы. Для неверных цен сначала нужно согласовать правило отказа и повторного ввода.

Фактические запуски — verification.json. Структурная проверка скилла не доказывает понимание студентом.
