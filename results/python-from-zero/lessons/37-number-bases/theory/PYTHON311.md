# 37. Мини-проект: системы счисления

После урока вы сможете: Объяснить позиционную запись и построить представление в другом основании.

Нужные знания: Цифры числа, while, индексы и функции

## От задачи к способу решения

В десятичной записи 243 означает 2 * 100 + 4 * 10 + 3. Разряды соответствуют степеням 10. **Основание системы счисления** задаёт число доступных цифр и вес каждого следующего разряда. В двоичной системе есть только 0 и 1, веса справа налево — 1, 2, 4, 8 и далее.

Например, двоичное 1101 — это 1 * 8 + 1 * 4 + 0 * 2 + 1 = 13. Само число не меняется от выбора записи: меняется способ показать его цифрами. В шестнадцатеричной системе нужны шестнадцать обозначений, поэтому после 0–9 используются A, B, C, D, E, F для значений 10–15.

Как получить цифры из десятичного значения? Для основания 10 мы брали остаток и делили на 10. То же правило действует для base: остаток remaining % base — младшая цифра, целое деление убирает этот разряд. Для 13 и основания 2 шаги дают остатки 1, 0, 1, 1. Их порядок справа налево, поэтому перед выводом разворачиваем список.

В строке digits = '0123456789ABCDEF' символ по индексу digit обозначает значение нужной цифры. Для остатка 10 берём A. Нельзя просто превращать остаток 10 через str: получится две позиции '10', а нужна одна цифра A.

Ноль разбираем отдельно: его запись '0'. Обычный while remaining > 0 не выполнится, поэтому без специального случая получилась бы пустая строка. Основание должно быть не меньше 2: при base = 1 деление не уменьшает положительное remaining, и цикл не завершится. Верхняя граница 16 согласована с длиной таблицы digits.

Python умеет эти преобразования и готовыми средствами: bin(number) показывает двоичную строку с префиксом 0b, hex(number) — шестнадцатеричную с префиксом 0x и строчными буквами. `int(text, base)` получает значение из текстовой записи в указанном основании. Однако сначала написанный вручную способ помогает понять, откуда берётся результат и почему требуется обратный порядок.

Сравните 13 в основаниях 2 и 16: 1101 и D. Обе записи можно снова прочитать через int с соответствующим основанием и получить 13. Это сильная проверка преобразования: мы сравниваем с независимым стандартным разбором записи.

Длина записи связана с числом делений. Для двоичного 13 рабочие значения идут 13 → 6 → 3 → 1 → 0, всего четыре шага. Если увеличить число примерно вдвое, добавляется около одного двоичного разряда, а не вдвое больше шагов. Логарифм по основанию base описывает число таких последовательных делений; точное число цифр для положительного number равно целой части этого логарифма плюс 1. Вычислять логарифм в программе не нужно: цикл сам определяет число шагов.

## Задача и формат данных

Перевести неотрицательное десятичное целое в основание от 2 до 16.

**Ввод:** Число и основание отдельными строками.

**Вывод:** Запись без префикса; цифры старше 9 — заглавные A–F.

**Допустимые данные:** 0 <= number <= 1000000000; 2 <= base <= 16.

Вход сквозного примера:

```text
13
2
```

Ожидаемый вывод:

```text
1101
```

## Пройдём пример руками

| Шаг | Действие и причина | Состояние или результат |
| --- | --- | --- |
| 1 | 13 % 2 = 1, деление оставляет 6 | parts = ['1'], remaining = 6 |
| 2 | 6 % 2 = 0, деление оставляет 3 | parts = ['1', '0'], remaining = 3 |
| 3 | 3 % 2 = 1, деление оставляет 1 | parts = ['1', '0', '1'], remaining = 1 |
| 4 | 1 % 2 = 1, деление оставляет 0 | parts = ['1', '0', '1', '1'], remaining = 0 |
| 5 | Развернуть младшие цифры в привычный порядок | 1101 |

## Полная программа

```python
def to_base(number, base):
    if number == 0:
        return '0'
    digits = '0123456789ABCDEF'
    parts = []
    remaining = number
    while remaining > 0:
        digit = remaining % base
        parts.append(digits[digit])
        remaining //= base
    return ''.join(parts[::-1])

number = int(input())
base = int(input())
print(to_base(number, base))
```

## Как читать реализацию

remaining хранит часть, ещё не разобранную на разряды. parts хранит символы младших цифр сначала. Обратный срез меняет порядок, join убирает границы между частями. digits — таблица соответствия значений цифр их записи, её размер фиксирован.

## Почему работает и сколько действий требуется

На каждом шаге remaining = quotient * base + remainder. Остаток задаёт правильную младшую цифру, а quotient — остальные разряды. Повторение извлекает все цифры. При base >= 2 положительное remaining уменьшается и достигнет нуля. Для d цифр работа и дополнительная память пропорциональны d; d растёт примерно как логарифм number по основанию base. Это оценка для указанного диапазона обычных целых.

## Границы и частые ошибки

Отрицательные числа исключены; для них пришлось бы отдельно оформить знак и переводить модуль. Формат вывода требует заглавные A–F и не включает префиксы 0b или 0x.
