# 34. Мини-проект: угадай число

После урока вы сможете: Соединить игровой цикл, подсказки и несколько способов завершения.

Нужные знания: Функции, return, for и сравнения

## От задачи к способу решения

Проект собираем из частей, которые уже умеем объяснять. Секрет известен программе; игрок на каждом шаге предлагает число. Если догадка ниже секрета, надо искать большее число; если выше — меньшее. Равенство завершает игру. После заданного количества промахов игра тоже завершается.

Сначала напишите правила на бумаге. У секрета 11 и догадок 5, 15, 11 результат: БОЛЬШЕ, МЕНЬШЕ, УГАДАНО 3. Подсказка относится к следующей догадке, поэтому при 5 нельзя напечатать МЕНЬШЕ только потому, что само введённое число меньше секрета.

Функция play получает секрет и лимит. Номер попытки проходит range от 1 до лимита включительно. Внутри проверяем равенство раньше сравнений: после победы подсказка не нужна. return завершает весь вызов play. Если ни одна попытка не завершила функцию, команда после цикла сообщает об исчерпании лимита.

Для ручного разбора и автоматических проверок основной файл принимает секрет первым числом. Это позволяет повторить тот же пример. Игровая версия play.py в папке кода выбирает секрет сама и не показывает его игроку. Механизм сравнения в обеих версиях одинаковый.

Случайный выбор выполняется так: после `import random` вызов `random.randint(1, 100)` возвращает целое от 1 до 100 **включая обе границы**. Модуль random генерирует псевдослучайную последовательность — она определяется внутренним состоянием. `random.seed(7)` задаёт начальное состояние, полезное при проверке. В обычной игре фиксированный seed не ставят, чтобы каждый запуск не повторял один и тот же сценарий.

Секрет выбирается один раз до игрового цикла. Если выбирать его после каждой догадки, цель будет меняться, а подсказки станут противоречивыми. Это различие между настройкой проекта и состоянием текущей попытки.

Порядок самостоятельной работы: реализуйте сравнение одной догадки → добавьте цикл → добавьте раннюю победу → проверьте исчерпание лимита → подключите случайный выбор. Так каждая следующая трудность имеет уже проверенную основу. Обработку некорректных догадок добавляйте после работающих базовых правил.

## Задача и формат данных

Провести игру с ограничением попыток и подсказками относительно секретного числа.

**Ввод:** Секрет, затем лимит попыток отдельными строками; далее догадки до победы либо исчерпания лимита.

**Вывод:** После промаха БОЛЬШЕ или МЕНЬШЕ; при успехе УГАДАНО и номер попытки. После всех промахов ПОПЫТКИ ЗАКОНЧИЛИСЬ.

**Допустимые данные:** Секрет и догадки от 1 до 100, лимит от 1 до 100; все догадки — допустимые целые.

Вход сквозного примера:

```text
11
3
5
15
11
```

Ожидаемый вывод:

```text
БОЛЬШЕ
МЕНЬШЕ
УГАДАНО 3
```

## Пройдём пример руками

| Шаг | Действие и причина | Состояние или результат |
| --- | --- | --- |
| 0 | Секрет и лимит задаются до попыток | secret = 11, attempt_limit = 3 |
| 1 | 5 ниже секрета: нужен больший вариант | БОЛЬШЕ |
| 2 | 15 выше секрета: нужен меньший вариант | МЕНЬШЕ |
| 3 | 11 совпадает: return завершает игру | УГАДАНО 3 |

## Полная программа

```python
def play(secret, attempt_limit):
    for attempt in range(1, attempt_limit + 1):
        guess = int(input())
        if guess == secret:
            print('УГАДАНО', attempt)
            return
        if guess < secret:
            print('БОЛЬШЕ')
        else:
            print('МЕНЬШЕ')
    print('ПОПЫТКИ ЗАКОНЧИЛИСЬ')

secret = int(input())
attempt_limit = int(input())
play(secret, attempt_limit)
```

## Как читать реализацию

secret не меняется в play; attempt меняется по for. Успешный return пропускает не только остаток итерации, но и сообщение после цикла. Один break завершил бы цикл, но не пропустил сообщение после него. Для варианта с break нужен отдельный способ различить победу и исчерпание попыток, например флаг или проверка результата последней догадки.

## Почему работает и сколько действий требуется

Каждая догадка относится к одному из трёх случаев относительно неизменного секрета. Победа заканчивает функцию, а конечный диапазон ограничивает число промахов. Не больше t попыток, значит работа пропорциональна t, служебная память постоянна. Случайное начальное число не меняет корректность сравнения.

## Границы и частые ошибки

Базовая версия получает только правильные числовые догадки. Обработка пустых строк, выхода и неверного диапазона должна иметь правило: считаются ли они попыткой? Это уже изменение игрового контракта.
