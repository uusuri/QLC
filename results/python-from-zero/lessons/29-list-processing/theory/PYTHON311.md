# 29. Отбор, поиск и сортировка списка

После урока вы сможете: Сохранить подходящие элементы и объяснить, когда можно менять порядок.

Нужные знания: Циклы по спискам, append и копии

## От задачи к способу решения

**Отбор**, или фильтрация, оставляет элементы, удовлетворяющие правилу. Вместо удаления из исходного списка создадим пустой positive. Для каждого value при value > 0 добавим его. Так порядок входа пока сохраняется, а повторы не исчезают: два подходящих элемента — два добавления.

**Сортировка** переставляет элементы по выбранному порядку. `positive.sort()` меняет существующий список по возрастанию. `sorted(positive)` возвращает новый отсортированный список, оставляя исходный неизменным. `reverse=True` задаёт убывание в обоих вызовах. sort возвращает None, поэтому `positive = positive.sort()` уничтожит связь имени со списком.

Для входа 3, −1, 3, 0, 2 отбор даёт [3, 3, 2], затем сортировка [2, 3, 3]. Количество три, а не два: мы не считаем различные значения. Сортировка чисел int и текстовых записей str различается. У строк '10' и '2' порядок начинается с первого символа, поэтому '10' идёт раньше '2'. Для числового порядка преобразуйте ввод в int до сортировки.

**Линейный поиск** проходит элементы по очереди. Можно спросить `target in numbers`, если нужен только факт наличия. `numbers.index(target)` возвращает первый индекс, но при отсутствии выдаёт ValueError. Чтобы получить −1 при отсутствии, можно пройти индексы вручную, начать position = −1, при совпадении сохранить index и сделать break.

Сортировка допустима, когда порядок входа не является частью ответа. Если нужно вернуть первые положительные числа по времени поступления, sort нарушит задачу. Для поиска исходного номера максимума тоже нельзя сначала переставить значения и забыть старые номера.

Подбирайте операции по потребности: одной сумме сортировка не нужна; упорядоченному выводу нужна. На маленьком примере это почти незаметно, но лишняя сортировка увеличивает работу с линейного прохода до порядка n log n сравнений в худшем случае для готовой сортировки CPython.

Расшифруем эту оценку. n — число элементов, а log₂ n описывает число последовательных делений пополам. Для степеней двойки это точное число делений до 1: для 8 — 3, для 16 — 4. Для других n целое число шагов может требовать округления. Поэтому n log n растёт быстрее n, но медленнее n². Здесь это свойство готовой операции сортировки, а не вывод из одного вызова sort. CPython — обычная реализация Python, в которой проверен код курса. Реализацию сортировки писать сейчас не требуется; её описание находится в [материалах CPython](https://github.com/python/cpython/blob/3.11/Objects/listsort.txt). В оценках роста основание логарифма обычно опускают, потому что оно меняет только постоянный множитель.

## Задача и формат данных

Из целых чисел выбрать положительные и вывести их по возрастанию.

**Ввод:** Одна строка целых чисел через пробел, возможно пустая.

**Вывод:** Количество выбранных первой строкой, отсортированные выбранные числа второй.

**Допустимые данные:** До 1000 элементов, значения от −10000 до 10000; повторы сохраняются.

Вход сквозного примера:

```text
3 -1 3 0 2
```

Ожидаемый вывод:

```text
3
2 3 3
```

## Пройдём пример руками

| Шаг | Действие и причина | Состояние или результат |
| --- | --- | --- |
| 1 | 3 подходит, -1 нет, следующая 3 подходит | positive = [3, 3] |
| 2 | 0 не положителен, 2 подходит | positive = [3, 3, 2] |
| 3 | sort переставляет элементы по числовому возрастанию | positive = [2, 3, 3] |

## Полная программа

```python
tokens = input().split()
positive = []
for token in tokens:
    value = int(token)
    if value > 0:
        positive.append(value)
positive.sort()
print(len(positive))
print(*positive)
```

## Как читать реализацию

tokens хранит части исходной строки, value — очередное преобразованное число. positive сохраняет только подходящие числа. После sort порядок изменён намеренно. Сумма не вычисляется: ответ требует количество и конкретную последовательность.

## Почему работает и сколько действий требуется

Каждый положительный элемент добавляется один раз и никакой другой не добавляется. Сортировка меняет только порядок, сохраняя элементы и повторы. Для n входных элементов и k выбранных отбор линейный, сортировка до порядка k log k, общий худший порядок n log n. Хранение частей ввода, выбранных элементов и служебной памяти сортировки линейно.

## Границы и частые ошибки

Пустой список можно сортировать и выводить. Поиск index в пустом списке выдаст ValueError. Если нужен прежний порядок, пропустите сортировку.
