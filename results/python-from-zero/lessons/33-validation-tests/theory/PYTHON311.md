# 33. Неверный ввод и проверка функций

После урока вы сможете: Обработать ожидаемую ошибку преобразования и проверить контракт функции.

Нужные знания: Функции, return, if и сообщения об ошибках

## От задачи к способу решения

В задачах раньше гарантировался правильный ввод. В программе для человека опечатка ожидаема. **Проверка ввода** отделяет допустимые данные от неправильных и даёт понятный ответ. Сначала проверим возможность получить целое число, затем его диапазон: это разные причины отказа.

`try` начинает блок, где возможна ожидаемая ошибка. `except ValueError` задаёт действие при конкретном исключении ValueError. `else` у try выполняется только если блок try закончился без исключения. Это другое применение слова else, отдельное от if и циклов.

Разместим внутри try только `age = int(text)`. Если введено abc или 18.5, преобразование невозможно: печатаем ЧИСЛО. Если преобразование удалось, в else проверяем отрезок от 0 до 120. Для 121 печатаем ДИАПАЗОН; для 18 — ПРИНЯТО.

Не пишите пустой общий except, который прячет любые ошибки. Опечатка в имени или неверный алгоритм требуют исправления кода, а не сообщения «плохой пользователь». Перехватываем только ту ошибку, которую ожидаем от оговорённого действия.

Вычисляющие функции удобно проверять **утверждениями assert**: `assert expression` требует, чтобы expression было истинным, иначе возникает AssertionError. Например, после отдельного определения is_even можно проверить assert is_even(0) и assert not is_even(3). Это проверка собственного кода, а не механизм защиты ввода: при оптимизированном запуске Python проверки assert могут отключаться.

Для каждой функции подготовьте случаи: обычный, минимальный, граничный и такой, который ломает правдоподобную ошибку. Для count_positive нужны пустой список, одни отрицательные, ноль и положительные. Проверка одного [1, 2] не обнаруживает ошибку >= 0 вместо > 0.

**Декомпозиция** — разделение программы на понятные части. Ввод и сообщения могут находиться снаружи, а функция in_age_range(age) отвечает только за числовое правило. Это позволяет тестировать правило без ожидания input. Контракт функции: принимает целое и возвращает bool; ошибки преобразования в её работу не входят.

## Задача и формат данных

Проверить ввод возраста: текст должен быть целым числом от 0 до 120.

**Ввод:** Одна произвольная строка длиной до 100 символов.

**Вывод:** ЧИСЛО для неподходящей числовой записи, ДИАПАЗОН для целого вне границ, ПРИНЯТО для допустимого возраста.

**Допустимые данные:** Принимается любой текст указанной длины; целое преобразуется стандартным int.

Вход сквозного примера:

```text
121
```

Ожидаемый вывод:

```text
ДИАПАЗОН
```

## Пройдём пример руками

| Шаг | Действие и причина | Состояние или результат |
| --- | --- | --- |
| 1 | Получить текст 121 | text = 121 как строка |
| 2 | int успешно создаёт целое, except не выполняется | age = 121 |
| 3 | Число выше включённой верхней границы | in_age_range(age) = False |
| 4 | Выбрать сообщение об ошибке диапазона | ДИАПАЗОН |

## Полная программа

```python
def in_age_range(age):
    return 0 <= age <= 120

text = input()
try:
    age = int(text)
except ValueError:
    print('ЧИСЛО')
else:
    if in_age_range(age):
        print('ПРИНЯТО')
    else:
        print('ДИАПАЗОН')
```

## Как читать реализацию

in_age_range не печатает и не читает, только возвращает результат числовой проверки. В except попадают исключительно ошибки int в данном try. Ветвь else выполняется при доступном age; поэтому попытки использовать несуществующее значение после неудачного преобразования нет.

## Почему работает и сколько действий требуется

Каждая строка либо не преобразуется, либо создаёт целое внутри диапазона, либо создаёт целое вне него. Эти случаи не пересекаются и полностью покрывают ввод по контракту. Для длины L чтение и преобразование требуют работы по длине, хранится исходный текст и результат.

## Границы и частые ошибки

Пустая строка тоже получает ЧИСЛО. EOFError при отсутствии строки вообще не то же, что пустая введённая строка, и здесь не перехватывается. assert в учебных тестах не заменяет явную обработку неправильного ввода.
