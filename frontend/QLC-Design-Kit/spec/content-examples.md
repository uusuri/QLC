## Задача014 / Две суммы

**Условие.** Дан массив целых чисел `nums` и число `target`. Верните индексы двух разных элементов, сумма которых равна `target`. В примере гарантируется ровно одна подходящая пара; один элемент нельзя использовать дважды.

**Вход.** Первая строка содержит `n` и `target`. Вторая — `n` целых чисел.

**Выход.** Два индекса элементов, начиная с0, в любом порядке.

**Пример.** Вход: `4 9` и следующая строка `2 7 11 15`. Выход: `0 1`.

**Ограничения.** `2 ≤ n ≤100000`, `-10^9 ≤ nums[i], target ≤10^9`. Использовать безопасную числовую модель для промежуточных операций в выбранном языке. Это демонстрационная постановка, не существующий task DTO.

**Подсказка закрыта.** «Какая информация о просмотренных элементах поможет проверить следующий?»

Toolbar совместимого режима: `Main.java` · Java21 · «Сохранено на этом устройстве» · «Сбросить код». Основное действие «Проверить решение», после сбоя polling «Обновить статус». Встроен именно существующий Monaco.

Future controls: «Запустить» запускает пользовательский input и не завершает задачу; «Полный экран» меняет только окружение editor; Console / Tests / Results требуют соответствующих API. В локальном UI-пакете эти состояния — placeholders, не новая реализация редактора.

Marker: TRANSFER / UNGUIDED. Title: «Сводка заказов».

«Сервис получает события об оплате. Одно событие может прийти несколько раз, а порядок поступления не гарантирован. Подготовьте обработку, при которой каждый заказ учитывается в дневной сумме один раз».

Submission: code/text/link по типу сценария. Accepted: «Сводка корректна для повторных и переставленных событий». Failed: «Повтор события изменяет итоговую сумму» без раскрытия скрытого теста. After completion: объяснение идеи идентичности события и идемпотентной обработки, без утверждения, что существует только один правильный инструмент.

## Глобальная речь интерфейса

Фактическая и короткая. «Сохранено», «Не удалось загрузить», «Проверить решение», «До следующего уровня660XP». Не «Запусти свой потенциал», не «Стань легендой кода». Технические подписи помогают различать тип активности и контекст; случайные коды не маскируются под реальные статусы системы.

Dates и numbers локализуются:9сентября2026,3 990 ₽,21 840 XP. Текст получает пробелы и переносы в реальной typography; сокращённые записи в таблицах этой спецификации обозначают данные, а не финальную строку UI.
