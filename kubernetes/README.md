# Запуск с локальным Kubernetes

Redis работает в Kubernetes, backend и frontend пока запускаются на хосте
через `run.sh`. Dev использует PostgreSQL из Compose, prod подключается к Neon.
Окружения запускаются в разных профилях minikube: остановка dev не выключает prod.

| Режим | Профиль и контекст minikube | Namespace | Redis на хосте | PostgreSQL |
| --- | --- | --- | --- | --- |
| dev | `minikube` | `qlc-dev` | `127.0.0.1:16379` | Docker Compose |
| prod | `qlc-prod` | `qlc-prod` | `127.0.0.1:16380` | Neon |

Все команды выполняются из корня QLC. Для minikube явно указан контекст,
чтобы команды не зависели от выбранного по умолчанию кластера.

## Хранение Redis

Redis использует PVC `data-redis-0` и AOF с синхронизацией раз в секунду.
PVC сохраняет данные при пересоздании Pod, но не заменяет резервные копии
и не переносит данные на другой компьютер. Содержимое прежнего Redis из
Compose не импортируется: при первом запуске окружение начинает с пустой
очереди и пустых корзин. Старые контейнеры и тома Compose не удаляются.
Ожидающие отправки из PostgreSQL могут повторно попасть в очередь через recovery.

## Dev

В игнорируемом `.env.dev` задайте:

```dotenv
REDIS_HOST=127.0.0.1
REDIS_PORT=16379
```

При работающем Docker Desktop достаточно одной команды из корня QLC:

```sh
./run.sh dev
```

Скрипту нужны `minikube` и `kubectl`. После сборки приложения он:

1. Запускает профиль выбранного окружения, если кластер ещё не работает.
2. Применяет `kubernetes/<режим>/redis.yaml` и ждёт готовности Redis.
3. Создаёт фоновый port-forward на локальный `REDIS_PORT` и проверяет Redis через PING.
4. Для dev поднимает PostgreSQL через Compose, затем запускает backend и frontend.

## Prod

В игнорируемом `.env.prod`:

```dotenv
REDIS_HOST=127.0.0.1
REDIS_PORT=16380
```

Параметры подключения к Neon, JWT и почтовые ключи остаются в этом же файле.
Prod запускается только из чистой ветки `main`, как и раньше:

```sh
./run.sh prod
```

Скрипт собирает frontend для prod, поднимает отдельный профиль `qlc-prod`,
применяет `kubernetes/prod/redis.yaml`, создаёт port-forward и запускает приложение.
Compose для prod больше не используется. Первый запуск нового профиля может
скачивать образы Kubernetes. Каждый профиль — отдельный локальный кластер,
поэтому одновременно запущенные dev и prod требуют ресурсов для обоих кластеров.

## Остановка

Ctrl+C завершает frontend, backend и port-forward, затем выполняет
`minikube --profile=<профиль окружения> stop --keep-context-active`.
Выбранный профиль останавливается даже если работал до запуска скрипта;
его остальные нагрузки тоже остановятся. PVC и данные сохраняются. Другой
профиль, Docker Desktop и контейнер PostgreSQL остаются работать.
Ошибка после начала запуска Kubernetes вызывает
такую же очистку; ошибка сборки или занятый порт не останавливает кластер.

Если port-forward завершится, скрипт остановит выбранное окружение и кластер
с сообщением об ошибке. Для повторного подключения запустите `run.sh` снова.
Ручной port-forward из отдельного терминала перед первым запуском нужно
остановить: скрипт не занимает чужой порт и не завершает чужие процессы.

Для ручной проверки после запуска:

```sh
kubectl --context=minikube -n qlc-dev get pods,pvc,svc
kubectl --context=minikube -n qlc-dev exec redis-0 -- redis-cli ping
kubectl --context=qlc-prod -n qlc-prod get pods,pvc,svc
kubectl --context=qlc-prod -n qlc-prod exec redis-0 -- redis-cli ping
```

Ранее запущенный dev-контейнер Redis можно остановить отдельно:

```sh
docker stop qlc_redis
```

Эта команда не удаляет контейнер и его данные. Прежний prod-контейнер
`qlc_redis_prod` скрипт также не использует и не удаляет. `docker-compose.prod.yml`
остаётся для ручного доступа к старому Redis; `run.sh prod` его не запускает.

## Проверка запуска и остановки

```sh
node --test scripts/tests/run-lifecycle.test.cjs
```

Проверки запускают `run.sh` во временной папке с подставными командами.
Они проверяют очистку процессов при Ctrl+C, ошибках запуска и потере
port-forward, отдельные профили/контексты/namespace и порты dev и prod,
а также запрет запуска prod из develop или с незакоммиченными изменениями. Настоящие
Docker, minikube, backend и frontend в этих проверках не запускаются.
