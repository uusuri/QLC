# Запуск backend

Секреты хранятся в корневом `.env`, который исключён из Git. Для новой установки
скопируйте `.env.example` в `.env` и заполните `POSTGRES_PASSWORD` и `JWT_SECRET`.
Не перезаписывайте существующий `.env`: он содержит локальные настройки.

Оба профиля, `dev` и `prod`, используют `POSTGRES_DB`, `POSTGRES_USER`,
`POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT`. Docker Compose использует
те же переменные. Для существующей БД пароль в `.env` должен совпадать с паролем
роли PostgreSQL; редактирование `.env` само по себе пароль в БД не меняет.

`JWT_SECRET` обязателен и должен содержать не менее 64 байт UTF-8.
Создать случайное значение можно командой `openssl rand -hex 64`; запишите
результат в `.env`, не в репозиторий. Смена ключа делает старые JWT недействительными.

Из каталога `backend` в **fish**, как в текущем способе запуска:

```fish
export (string match -rv '^\s*(#|$)' < ../.env)
./gradlew bootRun
```

Для этого способа в `.env` нужны строки `KEY=value` без кавычек, без `export`
и без комментариев после значения. Для zsh/bash синтаксис другой:

```sh
set -a
source ../.env
set +a
./gradlew bootRun
```

Для профиля `prod` установите `SPRING_PROFILES_ACTIVE=prod` в окружении.
Тесты используют отдельную H2-базу и временный случайный JWT-ключ; `.env` им не нужен.

## Подтверждение почты и сброс пароля

Для отправки писем через Resend добавьте в игнорируемые `.env.dev` и `.env.prod`
`RESEND_API_KEY` (ключ с правом отправки) и `MAIL_FROM=no-reply@mail.qlcode.me`.
Укажите `FRONTEND_PUBLIC_URL=http://127.0.0.1:3000` для dev и
`FRONTEND_PUBLIC_URL=https://qlcode.me` для prod. Не переносите ключ в Git.
Если отправку намеренно нужно отключить, установите `APP_MAIL_ENABLED=false`;
при включённой отправке без ключа backend не стартует.

После регистрации письмо с подтверждением отправляется после сохранения пользователя.
В профиле можно запросить ссылку повторно. Ссылка действует 24 часа.
Страница «Забыли пароль?» отправляет одноразовую ссылку на почту аккаунта;
она действует 30 минут. Сброс пароля завершает старые сеансы. Письмо для
несуществующего аккаунта не отправляется, но API отвечает одинаково, чтобы не
раскрывать наличие адреса. Успешный сброс подтверждает владение почтой даже
для старого аккаунта без подтверждения. Telegram-аккаунты в этом механизме
не участвуют, поскольку их технический email не является адресом пользователя.

Миграция V14 добавляет таблицу одноразовых токенов и поля пользователя.
Миграция V15 один раз отмечает все уже существующие аккаунты
подтверждёнными; их данные не удаляются. Новые регистрации требуют
подтверждения по письму.
После обновления всем придётся войти заново, поскольку старые JWT не содержат
версии авторизации. Тесты отключают реальную отправку писем.

## Telegram и ранее раскрытые секреты

`TELEGRAM_BOT_TOKEN` читается только из окружения. Пустое значение отключает
Telegram-вход; обычный вход остаётся доступен. После утечки токен необходимо
отозвать и перевыпустить через BotFather, заменить значение в `.env`, повторно
экспортировать переменные и перезапустить backend. Перенос токена в `.env`
не является его отзывом.

Удаление значений из текущих файлов не удаляет их из старых коммитов или копий
репозитория. Ранее опубликованные JWT-ключи и пароли нельзя использовать при
развёртывании. История Git этим изменением не переписывается.

## Ошибки API

Ошибки возвращаются в JSON с полями `code`, `message`, `traceId`, `fieldErrors`.
Отсутствующий объект — 404, неверный ввод — 400, конфликт данных — 409,
ошибка аутентификации — 401, запрет доступа — 403. Неожиданная ошибка — 500
с безопасным текстом; подробности доступны в серверном логе по `traceId`.

## Доступ к учебным материалам

Публичный `GET /api/lessons/{id}` возвращает только описание урока без `contentMd`.
Публичный `GET /api/lessons/{id}/task-outline` возвращает только `id` и `taskType`,
без условий задач; для неопубликованного урока или курса список пуст.

Материалы и условия доступны вошедшему пользователю через
`GET /api/lessons/{id}/learn`, если курс бесплатный или куплен этим пользователем.
И курс, и урок должны быть опубликованы. Приватные тесты и правильные ответы
в ученический ответ не включаются. Ответ `/learn` имеет `Cache-Control: private, no-store`.

Администратор получает полный урок, включая черновики, через
`GET /api/admin/lessons/{id}`, а задачи — через защищённые маршруты
`GET /api/lessons/{id}/tasks` и `GET /api/tasks/{id}`.

## Восстановление очереди решений

При начале проверки в БД сохраняются `started_at`, уникальный `execution_token`
и счётчик фактических запусков `retry_count`. Переход `QUEUED → COMPILING`
проходит под блокировкой строки: повторная доставка не запускает вторую проверку.
Результат принимается только от текущей попытки. Запоздалые результат или ошибка
старого worker не могут изменить новую попытку.

Recovery каждые 5 секунд возвращает `COMPILING` и `RUNNING`, начатые более
15 минут назад, в `QUEUED`. Для старых записей без `started_at` используется
`created_at`. Публикация в Redis происходит после фиксации транзакции.
Записи `QUEUED` повторно публикуются не чаще раза в 10 секунд, партиями по 50;
ошибка Redis сохраняет их для следующего прохода. После трёх запусков без
результата решение завершится с `INFRA_ERROR`, а не будет повторяться бесконечно.

Worker использует [XAUTOCLAIM](https://redis.io/docs/latest/commands/xautoclaim/)
для pending-сообщений, которые не обрабатывались 15 минут, включая сообщения
других consumers. Курсор сканирования сохраняется между проходами.
По умолчанию каждый процесс получает уникальное имя; если задан `WORKER_ID`,
оно должно быть уникальным среди одновременно работающих процессов.

После сохранения окончательного результата `XACK` и `XDEL` выполняются одним
атомарным Lua-скриптом. Дубликаты уже завершённых решений тоже удаляются.
Сообщения активных попыток и сообщения при ошибке БД остаются pending.
Поток предназначен для **одной consumer group**; удаление payload не подходит
для независимых подписчиков. Старые записи, ACK-нутые прежней версией backend,
автоматически не очищаются. Непрочитанные и незавершённые сообщения не обрезаются
по длине: при недостаточной производительности worker очередь может расти.

Настройки можно переопределить переменными окружения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_SUBMISSIONS_RECOVERY_EXECUTION_TIMEOUT_MS` | `900000` | Возраст зависшей проверки |
| `APP_SUBMISSIONS_WORKER_RECLAIM_MIN_IDLE_MS` | `900000` | Минимальное время без доставки для reclaim |
| `APP_SUBMISSIONS_RECOVERY_POLL_DELAY_MS` | `5000` | Интервал recovery |
| `APP_SUBMISSIONS_WORKER_POLL_DELAY_MS` | `500` | Интервал опроса Redis |
| `WORKER_ID` | случайное имя | Уникальное имя worker |

Таймаут recovery должен быть больше максимальной длительности Docker runner
(сейчас до 10 минут плюс очистка). Планировщик использует два потока, чтобы
проверка кода не задерживала recovery. Доставка остаётся как минимум однократной:
после сбоя возможен повторный запуск, но устаревшая попытка не перезапишет результат.

Требуется Redis 6.2 или новее; в Docker Compose используется Redis 7.2.
При обновлении остановите старые экземпляры backend и запустите новую версию:
Flyway применит V6. Старые workers не поддерживают `execution_token`, поэтому
не следует оставлять их работать одновременно с новой версией.

Тестовый профиль отключает автоматический worker и recovery. Интеграционные
тесты вызывают их явно: используют H2 и отдельные временные ключи локального
Redis, затем удаляют эти ключи. Для `./gradlew test` нужен Redis на localhost:6379.

## TEST и NUMERIC

`POST /api/tasks/{taskId}/answers` принимает один вид ответа:

- TEST: `{"selectedOptionIndexes":[0,2]}`. Индексы начинаются с нуля; сравниваются
  множества с точным совпадением. Порядок и повтор индексов не меняют результат.
  Пустой ответ, индекс вне вариантов или несколько вариантов в задаче с одним
  правильным ответом — ошибка 400.
- NUMERIC: `{"numericAnswer":"-12.5000"}`. Значение обязательно передаётся JSON-строкой;
  сравнение использует `BigDecimal.compareTo()`, без погрешности. Интерфейс заменяет
  запятую на точку; API принимает обычную десятичную запись без экспоненты.

Ответ 201 содержит обычный `SubmissionResponse` со статусом `FINISHED` и вердиктом
`AC` или `WA`. Попытка сохраняется в `submissions.submitted_answer`; поля кода
и языка остаются NULL. Redis и Docker для этих задач не используются.
Некорректный запрос не создаёт попытку. GET submission сохраняет проверку владельца.

Перед созданием любой попытки, включая CODE, проверяются публикация урока и курса,
а также покупка курса (если он платный). Родительский урок и курс определяются
по связям задачи в БД. Правильные ответы не возвращаются ученику; для TEST DTO
передаёт только `multipleAnswersAllowed`. Ответ `/learn` также содержит
`hasAccess` и `acceptedTaskIds`, чтобы интерфейс сохранял отметки и переход дальше
после перезагрузки. Каждый уникальный AC учитывается в существующем прогрессе.

V7 снимает NOT NULL с языка и кода, добавляет `submitted_answer` и явный порядок
вариантов TEST. Для старых вариантов без поля порядка миграция однократно берёт
их текущий физический порядок; исходный порядок до возможных прежних перестановок
в БД восстановить невозможно. После миграции порядок хранится явно.

## Языки мультиязычного курса

У курса есть `multilingual` и `availableLanguages`; администратор меняет их в форме курса.
`user_courses.selected_language` хранит выбор отдельно для каждой пары пользователь–курс.
`GET/PUT /api/courses/{id}/language` доступны авторизованному пользователю с доступом к курсу;
PUT принимает `{ "selectedLanguage": "PYTHON312" }`. Первый выбор в бесплатном курсе
добавляет его в пользовательские курсы. В платном курсе выбор не выдаёт доступ.
Учебная карта `/api/users/me/learning-courses` возвращает `selectedLanguage`.
Если администратор убрал выбранный язык из курса, пользователю предлагается выбрать заново.

Миграция V9 отмечает «Алгоритмы и структуры данных» мультиязычным курсом и включает
C++, Java, Python, JavaScript, TypeScript, C#, C, Go, PHP и Rust. Это рабочая подборка
популярных языков для практики алгоритмов, не ранжирование. Ориентир для подбора:
[GitHub Octoverse](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/).
После V10 урок хранит базовый `contentMd` и словарь `contentByLanguage` в таблице
`lesson_theory_variants`. Администратор редактирует версии в форме урока. Пропущенное
поле при обновлении сохраняет старые версии; пустой словарь удаляет их.
`GET /api/lessons/{id}/theory` возвращает только версию для сохранённого языка пользователя
и проверяет доступ к опубликованному уроку. Ответ персональный, `private, no-store`.
Если версия не создана, API возвращает базовый текст с `fallback: true`, а интерфейс
явно сообщает об этом. У обычных курсов остаётся базовая теория.
В курсе алгоритмов добавлены все 490 версий: 49 уроков × 10 языков. Общие доказательства
не меняются, примеры кода и пояснения о числах, контейнерах и памяти адаптированы.
Условия задач, подсказки и фрагменты внутри TEST пока остаются общими.

По текущему продуктовому решению CODE-отправки мультиязычных курсов демонстрационные:
сохраняются со статусом `DEMO`, без verdict, с `counts_for_progress=false` и не попадают
в очередь выполнения. Язык запроса обязан совпадать с сохранённым выбором пользователя.
Существующие проверки одноязычных курсов и заданий TEST/NUMERIC не меняются.
Перед включением настоящей проверки на новых языках необходимы исполнители и проверка лимитов.

Черновики и последняя отправка разделены по пользователю, задаче, версии тестов и языку.
Старый черновик подхватывается только для исходного языка задачи; его запись не удаляется.
Проверка: `./gradlew test --tests '*CourseLanguageIntegrationTest'` — 14 сценариев,
включая все 10 языков, повторный выбор, изоляцию пользователей и контроль доступа.
