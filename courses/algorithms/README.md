# Проверка алгоритмических задач QLC

Материалы курса, языковые версии теории, задачи, подсказки и приватные тесткейсы
хранятся в PostgreSQL и редактируются через админку. Приложение не читает этот каталог.
Историю контента и резервное копирование БД следует организовать отдельно; Git не заменяет бэкапы БД.

Здесь сохранены только инструменты проверки 74 кодовых задач:

- `tasks/<slug>/solution.cpp` — эталонное решение;
- `tasks/<slug>/wrong.cpp` — типичная ошибка, которую тесты должны отсеивать;
- `tasks/<slug>/slow.cpp` — корректное медленное решение, где оно применимо;
- `authoring/cases.py` — генераторы и независимые проверяющие алгоритмы исходных задач;
- `authoring/expanded_cases.py` — отдельные проверяющие алгоритмы и максимальные тесты 12 новых задач;
- `authoring/foundation_cases.py` — базовые задачи, независимые малые проверки и максимальные входы;
- `authoring/validate.py` — запуск проверок в песочнице QLC;
- `task-index.json` — ключи задач и лимиты для локальной проверки;
- [SOURCES.md](SOURCES.md) — источники, использованные при разработке курса.

Лимиты в индексе относятся к сохранённым проверочным программам. Изменения условий
и лимитов в админке автоматически эти программы и генераторы не обновляют.

## Проверка

Нужны Docker и образ `qlc-cpp-runner:dev`, собранный из `sandbox/`.
Запуск из корня репозитория:

```sh
# Две вводные задачи
python3 courses/algorithms/authoring/validate.py --only sum increasing-run

# Все 74 кодовых задач
python3 courses/algorithms/authoring/validate.py
```

Тесткейсы генерируются во время запуска и передаются в контейнер через stdin.
Эталоны и медленные решения на малых входах должны получать AC. Ошибочные решения
должны отклоняться, а медленные — не проходить большие входы; ошибка компиляции
не считается успешной проверкой силы тестов.

Результаты появляются в `reports/`, исключённом из Git. Скрипт не подключается к БД
и не меняет курс или прогресс студентов. Копий теории, готовых пакетов курса
и скриптов повторного импорта в каталоге нет.
