# Префиксы и отложенные изменения

## Что вы научитесь делать

Отличать статические запросы от обновлений; применять префиксные и разностные массивы.

Предпосылки: Предыдущие модули, 01–01.

## Идея и алгоритм

Когда много запросов пересекаются, повторный просмотр каждого отрезка делает одну и ту же работу. В неизменяемом массиве заранее посчитайте p[0]=0 и p[i]=p[i−1]+a[i]. Тогда сумма включённого отрезка [l,r] равна p[r]−p[l−1]. Подготовка занимает O(n), каждый запрос — O(1); общая сложность O(n+q).

Выберите одну систему индексов и придерживайтесь её. В этом курсе большинство условий используют индексы с 1 и включённые границы. Для этого удобно хранить массив длины n+1. Полуоткрытый вариант [l,r) с нулевой индексацией тоже корректен, но смешивать формулы нельзя. Проверяйте запрос к одному элементу и запрос, начинающийся с первого.

Префиксная разность работает не для любой операции. Из prefix_max[r] и prefix_max[l−1] нельзя восстановить максимум участка: максимум не имеет обратной операции. Для суммы обратной операцией является вычитание. Аналогичный приём существует для XOR, поскольку x XOR x = 0.

Другая задача: прибавить x на многих отрезках, а итог вывести один раз в конце. Здесь храните изменения между соседними значениями — разностный массив d. Прибавление на [l,r] задаётся двумя событиями: d[l]+=x и d[r+1]−=x. После всех операций накопите префиксную сумму d. Ячейка n+1 нужна для закрытия изменения, доходящего до конца.

Префиксы ускоряют запросы при неизменном массиве, разности — пакетные изменения без промежуточных ответов. Если изменения и запросы чередуются, эти решения уже не дают O(1) на обе операции. Такой интерфейс позже приведёт к дереву Фенвика и дереву отрезков. Сначала выясняйте порядок операций, потом выбирайте структуру.

## Реализация на Rust

Индексы запросов начинаются с 1: выделите n+1 ячеек и оставьте нулевой префикс равным нулю. Для сумм до 2·10¹⁴ используйте `i64`, а для индексов — `usize`. Расширяйте тип до умножения: `i64::from(a) * i64::from(b)`, если a и b имеют тип `i32`. Не рассчитывайте на переполнение: поведение обычных операций зависит от режима проверок, а `checked_add` позволяет обработать выход за диапазон явно.

## Разберём пример

a=[3,−2,5,1], p=[0,3,1,6,7]. Сумма [2,4] равна 7−3=4. Для нулевого массива длины 5 операции +3 на [2,4] и −1 на [3,5] дают [0,3,2,2,−1].

## Где ошибаются

Закрытие прибавления ставится в r+1. Тип префиксов и изменений должен вмещать максимальную сумму, а не только одно входное число. Пустой префикс существует, даже если пустые запросы запрещены.

## Практика

- 03. Архив измерений: Для каждого запроса l, r найдите сумму a[l] + … + a[r]. Массив не меняется. Печатайте ответ на каждый запрос в отдельной строке.
- 04. Пакет изменений: Изначально массив из n чисел заполнен нулями. Каждая операция l r x прибавляет x ко всем элементам с l по r включительно. Выполните все операции, затем выведите итоговые элементы по одному в строке.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
