# Считаем сложность кода

В прошлом уроке мы сравнили два решения одной задачи. Здесь будем смотреть на небольшие фрагменты Rust и считать, сколько действий они выполняют.

После объяснения — 12 тестовых заданий. В каждом нужно выбрать один ответ. Программу писать не требуется.

## Какой ответ выбирать

В заданиях используется **Θ**, «тэта». Этой буквой обозначают точный порядок роста. Например, для 5n + 10 действий ответ — Θ(n), для 2n² + n — Θ(n²).

Почему не O? Запись O задаёт только верхнюю границу. Если программа делает n действий, оценки O(n) и O(n²) обе верны, но вторая сильно завышена. В тесте нам нужна оценка без такого завышения — Θ(n).

Если время зависит от содержимого массива, ищем худший случай. Например, поиск числа может закончиться на первом элементе. Но если числа в массиве нет, придётся проверить все n элементов: худшее время — Θ(n).

## Сначала посчитайте повторения

Во всех примерах work() обозначает одно простое действие, которое занимает постоянное время и не создаёт массивов. Сначала считаем вызовы work(), затем учитываем остальную работу циклов.

```rust
for _i in 0..n { work(); }
for _j in 0..n { work(); }
```

Первый цикл делает n вызовов, затем второй делает ещё n. Всего 2n: это Θ(n). Циклы идут **друг за другом**, поэтому числа повторений складываются.

Если второй цикл идёт до m, получится Θ(n + m). Убирать m нельзя: это другое число, и оно может оказаться гораздо больше n. А цикл ровно на 100 повторений даёт Θ(1), сколько бы элементов ни было во входном массиве.

Теперь поместим один цикл внутрь другого:

```rust
for i in 0..n {
    for _j in 0..i { work(); }
}
```

При i = 0 внутренний цикл не выполнится, при i = 1 выполнится один раз, при i = 2 — два. Всего 0 + 1 + … + (n − 1) = n(n − 1)/2 вызовов, то есть Θ(n²). Это та же сумма, что встретилась в медленном решении «Полосы роста».

## Если счётчик делится пополам

```rust
let mut x = n;
while x > 1 {
    work();
    x /= 2;
}
```

При n = 32 счётчик проходит значения 32, 16, 8, 4, 2, после чего становится равен 1 и цикл заканчивается. Получается пять повторений.

Число делений n пополам до единицы равно ⌊log₂n⌋. Знаки ⌊ ⌋ означают округление вниз. Для n = 32 логарифм равен 5, для n = 64 — 6. Время такого цикла — Θ(log n).

Здесь важно именно деление. Если вместо x /= 2 уменьшать счётчик на 2, понадобится примерно n/2 повторений: получится Θ(n).

## Вложенные циклы бывают разными

Если для каждого из n элементов заново запустить цикл с делением счётчика пополам, получим n·log n действий и Θ(n log n) времени.

Но что, если каждый внутренний проход становится короче?

```rust
let mut length = n;
while length > 0 {
    for _j in 0..length { work(); }
    length /= 2;
}
```

Для n = 16 будет 16 + 8 + 4 + 2 + 1 = 31 вызов. В общем случае сумма не меньше n и меньше 2n. Значит, время — Θ(n). Умножать n на число внешних итераций здесь нельзя: внутренний цикл только в первый раз имеет длину n.

Ещё один способ получить линейное время с вложенным while — **не возвращать его счётчик назад**. Если j объявлен перед внешним циклом и только растёт от 0 до n, то за всё выполнение счётчик j увеличится не больше n раз. Считая время, нужно сложить эти шаги с n внешними итерациями. В тесте будет такой пример: проверьте, где именно обнуляется j.

## Одна строка тоже может быть дорогой

`let copy = a.to_vec();` для среза целых создаёт новый вектор и копирует n чисел: Θ(n) времени и Θ(n) памяти. Заимствование `let copy = &a;` не создаёт копии данных. Если выполнить такое копирование n раз, получится Θ(n²) времени.

Поэтому длина кода ничего не говорит о скорости. У вызова функции или операции с контейнером нужно учитывать то, что происходит внутри.

## У рекурсии считаем все вызовы

```rust
fn visit(k: usize) {
    if k == 0 { return; }
    visit(k - 1);
    visit(k - 1);
}
```

После visit(n) появятся два вызова с n − 1. Каждый из них создаст ещё два — уже четыре вызова с n − 2. Дальше будет 8, 16 и так далее. Даже одинаковые аргументы вычисляются заново: результаты нигде не сохраняются.

Всего вызовов 1 + 2 + 4 + … + 2^n = 2^(n + 1) − 1. Время — Θ(2^n). Глубина рекурсии при этом всего n + 1: глубина показывает длину одной цепочки вызовов, а не число всех выполненных вызовов.

## Память считаем отдельно

В visit вторая ветвь начинается после завершения первой. В стеке одновременно лежит только одна цепочка из n + 1 вызовов, поэтому память — Θ(n), хотя время экспоненциальное.

То же правило действует для временных массивов. Если на каждой итерации создаётся массив из n чисел, а затем становится не нужен и нигде не сохраняется, одновременно хранится только один массив. Объём одновременно нужных данных — Θ(n). Реальное освобождение памяти может происходить позже, в зависимости от среды. Если сохранить все n таких массивов до конца программы, понадобится Θ(n²).

Вопрос о памяти — это вопрос о том, **сколько данных хранится в один момент**, а не сколько всего было создано за время работы.

## Можно переходить к заданиям

Сначала получите число повторений или сумму, а уже потом ищите подходящий ответ. Если не получается, откройте первую подсказку. Третья содержит полный разбор.

В заданиях n и m положительны; все числа помещаются в указанные типы. Сложение, сравнение и обращение к элементу массива считаем действиями постоянной стоимости. Дополнительную память считаем без уже переданного входного массива. Разбираем код так, как он написан: не предполагаем, что компилятор уберёт пустые вычисления или рекурсивные вызовы.
