# Итог основы: сочетание методов

## Что вы научитесь делать

Выбирать метод по состоянию задачи, совмещать сортировку, поиск, ДП и дек.

Предпосылки: Предыдущие модули, 01–15.

## Идея и алгоритм

В финале основы задача уже не сообщает название алгоритма. Пройдите один и тот же маршрут: сформулируйте медленное корректное решение, определите его дорогую часть, найдите структуру повторяющихся запросов, затем оптимизируйте именно её. Такой подход надёжнее угадывания шаблона по отдельному слову в условии.

В расписании с прибылью жадность по окончанию больше не подходит. Отсортируйте проекты по правой границе. dp[i] — максимальная прибыль среди первых i проектов. Для очередного проекта выбираем максимум между его пропуском и прибылью проекта плюс лучшим ответом для совместимого префикса. Последний совместимый проект находится бинарным поиском по окончаниям. Получается O(n log n), а не O(n²).

В задаче о прыжках dp[i]=a[i]+max(dp[j]) для j из предыдущих k позиций. Прямой перебор — O(nk). Но дорогая часть уже знакома: максимум в скользящем окне. Монотонный дек уменьшает её до амортизированного O(1), весь алгоритм становится O(n). Это пример оптимизации перехода, при которой смысл динамики остаётся прежним.

Отрицательные награды заставляют аккуратно определить старт. Если путь обязан начаться на первой платформе и закончиться на последней, нельзя подставлять ноль вместо плохого предыдущего результата: это разрешило бы начать путешествие в середине. База только dp[1]=a[1]. Допустимость пустого решения всегда берётся из условия, а не из удобной инициализации.

После решения попробуйте восстановить объяснение без кода: что хранится, почему переход перечисляет все возможности и почему отброшенное больше не понадобится. Сравните эталонный алгоритм с независимым перебором на маленьких данных. Подготовьте собственные контрпримеры к жадному выбору по прибыли и к обнулению отрицательного префикса. Завершение основы означает, что вы умеете выбирать и сочетать инструменты, а не только повторять их реализацию.

## Реализация на Rust

Для очереди и дека используйте `VecDeque<usize>`: `push_back`, `pop_front`, `pop_back`. Обычный `Vec::remove(0)` сдвигает оставшиеся элементы. Для расписания бинарный поиск нужен по отдельному массиву отсортированных окончаний.

## Разберём пример

Проекты [0,2) с прибылью 3, [2,4) с прибылью 3, [0,4) с прибылью 10: максимум количества равен 2, максимум прибыли равен 10. Для платформ [−5,−2,−3], k=2 лучший путь 1→3 даёт −8, а не 0.

## Где ошибаются

Поиск первой позиции с окончанием >l включает совместимые проекты, заканчивающиеся ровно в l. В прыжках удаляйте кандидатов старше i−k, а не саму допустимую границу.

## Практика

- 31. Проекты с прибылью: У проекта есть время начала l, окончания r и прибыль v. Выберите непересекающиеся проекты с максимальной суммарной прибылью. Интервалы полуоткрытые [l,r), проекты с общей границей совместимы. Можно не выбирать ничего.
- 32. Маршрут по платформам: Стоя на платформе 1, нужно дойти до платформы n, каждый раз прыгая вперёд на 1…k позиций. При посещении i получаете a[i], включая первую и последнюю. Найдите максимальную сумму; пропустить достижение n нельзя.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
