# Дополнение: дерево отрезков и lazy propagation

## Что вы научитесь делать

Проектировать агрегат узла и действие обновления; проверять нейтральный элемент и порядок композиции.

Предпосылки: Предыдущие модули, 01–17.

## Идея и алгоритм

Дерево отрезков разбивает массив на вложенные сегменты. Лист соответствует элементу, внутренний узел — объединению соседних сегментов. Для запросов нужна операция слияния: sum, min, max или более сложная характеристика. Слияние должно быть ассоциативным, а для непересечения нужен нейтральный элемент. Коммутативность не обязательна, поэтому порядок левой и правой частей сохраняйте.

Для максимального подмассива узел хранит четыре числа: сумму всего сегмента, лучший префикс, лучший суффикс и лучший участок. Пересекающий границу лучший участок равен left.suffix+right.prefix. Префикс либо целиком слева, либо включает всю левую часть и префикс справа; суффикс симметричен. При разрешённом пустом участке максимум в листе равен max(0,x).

Точечная правка меняет один лист и O(log n) его предков. Построение снизу вверх занимает O(n). Пробегать весь массив после каждой правки означает игнорировать уже посчитанные агрегаты.

Для массового прибавления и максимума храните отложенную метку lazy. При полном покрытии сегмента прибавьте x к максимуму и метке, не спускаясь. Перед частичным обращением передайте метку детям и очистите родительскую. После обновления детей пересчитайте агрегат родителя. Для суммы равномерная прибавка изменила бы агрегат на x·длину, а не просто x.

Ленивое обновление возможно только если действие над агрегатом корректно вычисляется без просмотра элементов. Например, добавление x ко всем элементам не позволяет просто прибавить x к лучшему подмассиву: измениться может его оптимальная длина. Поэтому задачи этого модуля разделяют «лучший участок + правка точки» и «максимум + прибавление на отрезке». Сочетание присваивания и прибавления требует явного порядка композиции меток; число 0 нельзя использовать как признак отсутствующего присваивания.

## Реализация на JavaScript

Детей и размеры можно хранить в `Int32Array`, суммы — в `Float64Array`, если они точно помещаются в Number. Для больших точных сумм нужен другой способ хранения, например массив BigInt. Не выделяйте новые массивы для каждого рекурсивного запроса: агрегат должен иметь постоянное число полей.

## Разберём пример

Сегмент [−2,5,−1] при разрешённом пустом участке: sum=2, prefix=3, suffix=4, best=5. Для максимума массива [−5,−3] нейтральным при непересечении служит −∞, иначе ноль испортит ответ.

## Где ошибаются

Не путайте максимум элемента с максимальной суммой участка. Перед частичным спуском выполняйте push. У составного агрегата сохраняйте порядок частей.

## Практика

- 35. Лучший участок после правки: После каждого присваивания a[p]=x найдите максимальную сумму непрерывного участка всего массива. Пустой участок разрешён и имеет сумму 0. Ответ после каждой правки — с новой строки.
- 36. Массовая коррекция: Операция + l r x прибавляет x всем значениям на [l,r]. Операция ? l r запрашивает максимум на [l,r]. Все отрезки включают обе границы.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
