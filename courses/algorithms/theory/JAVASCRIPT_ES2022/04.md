# Бинарный поиск по ответу

## Что вы научитесь делать

Выделять монотонный предикат и писать поиск с явным инвариантом границ.

Предпосылки: Предыдущие модули, 01–03.

## Идея и алгоритм

Бинарный поиск применим не только к массиву. Его сущность — поиск границы в упорядоченной последовательности значений логического предиката. Например, при малой грузоподъёмности расписание не помещается в k дней, а при достаточно большой помещается. Между false и true есть единственная граница.

Сначала решите задачу проверки для фиксированного ответа. В доставке при ёмкости C набирайте максимально длинную очередную группу. Если следующий вес не помещается, начинайте новый день. Положительность весов важна: поздние элементы не могут компенсировать уже превышенную сумму. Проверка занимает O(n). Предикат «потребовалось не больше k групп» монотонен по C.

Для поиска первого допустимого ответа можно держать включённый диапазон [lo,hi], содержащий минимум. Если mid допустим, hi=mid; иначе lo=mid+1. Цикл идёт пока lo<hi. Для последнего допустимого ответа удобно держать lo допустимым, hi недопустимым и завершать при hi−lo=1. Не соединяйте условия одного шаблона с обновлениями другого.

В расстановке точек предикат противоположный: чем больше минимальное расстояние, тем труднее выбрать k точек. После сортировки жадно выбирайте самое раннее допустимое место. Если удалось выбрать хотя бы k точек, расстояние достижимо. Для k≥2 граница max−min+1 заведомо недопустима, а 0 допустим.

Докажите монотонность отдельно от корректности проверки. Неправильная проверка, даже будучи монотонной, даст уверенно неверный результат. Верхнюю границу выводите из ограничений, а не выбирайте «достаточно большое число». Используйте lo+(hi−lo)/2, подходящий тип для границ поиска и случаи, когда оптимум совпадает с крайним значением. Число проверок логарифмическое по ширине диапазона, но каждая проверка имеет собственную стоимость.

## Реализация на JavaScript

Середину целочисленного диапазона округляйте вниз. Для Number используйте `lo + Math.floor((hi - lo) / 2)`. Не заменяйте деление побитовым сдвигом: он ограничивает число 32 битами.

## Разберём пример

Грузы [7,2,5,10,8], k=2. При C=17 получаются три группы: [7,2,5], [10], [8]. При C=18 — две: [7,2,5], [10,8]. Значит, 18 допустимо; поиск доказывает, что меньшего допустимого значения нет.

## Где ошибаются

Не переполняйте сумму весов. Для расстояния равенство допустимо. Сначала сортируйте координаты. Обновление lo=mid при lo+1=hi может зациклить включённый поиск.

## Практика

- 07. Доставка по дням: Грузы идут в заданном порядке. Разбейте последовательность на не более k непустых непрерывных групп. Минимизируйте максимальную сумму одной группы. Выведите этот минимум.
- 08. Расстановка станций: Выберите k из n заданных различных координат. Максимизируйте минимальное расстояние между соседними выбранными точками. Выведите расстояние.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
