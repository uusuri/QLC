# Дополнение: паросочетания и потоки

## Что вы научитесь делать

Использовать увеличивающие пути, остаточную сеть и разрез как сертификат оптимальности.

Предпосылки: Предыдущие модули, 01–22.

## Идея и алгоритм

В двудольном паросочетании каждую левую и правую вершину можно использовать не более одного раза. Жадно взять доступную пару недостаточно: выбранное ребро может занять единственного партнёра другой вершины. Увеличивающий путь чередует невыбранные и выбранные рёбра и начинается и заканчивается свободными вершинами. Переворот статуса рёбер увеличивает число пар на один.

Алгоритм Куна ищет такие пути последовательно и имеет оценку O(VE). Хопкрофт—Карп группирует поиск в фазы: BFS определяет длину кратчайших увеличивающих путей, затем DFS по слоям находит их непересекающийся набор. Длина следующего кратчайшего пути возрастает, что даёт O(E√V) с учётом вершин в представлении. Храните соответствия обеих долей и отмечайте неудачные состояния фазы.

Поток обобщает выбор путей на ёмкости. На каждой дуге 0≤f≤c; во внутренних вершинах входящий поток равен исходящему. Цель — максимизировать выход из истока. Остаточная сеть содержит прямую остаточную ёмкость c−f и обратную f. Обратная дуга позволяет отменить прежний выбор и перенаправить поток; это не ребро исходной сети.

Встречные исходные дуги требуют собственных пар остаточных рёбер. Параллельные дуги тоже нельзя молча перезаписывать. Удобно хранить у каждой дуги индекс её обратной дуги. При отправке z уменьшайте прямую остаточную ёмкость и увеличивайте обратную.

Диниц строит BFS-уровни остаточной сети и посылает блокирующий поток только по переходам на следующий уровень. Указатель текущего ребра не даёт бесконечно пересматривать уже бесполезные рёбра одной фазы. Когда сток недостижим, найденный поток максимален: достижимые из истока вершины задают разрез с той же ёмкостью. В общем случае оценка Диница O(V²E), память O(V+E). Это стандартный подход для размеров задачи, а не утверждение, что более быстрых потоковых алгоритмов не существует.

## Реализация на JavaScript

Остаточные рёбра храните парами с индексами обратных рёбер. Детей и размеры можно хранить в `Int32Array`, суммы — в `Float64Array`, если они точно помещаются в Number. Для больших точных сумм нужен другой способ хранения, например массив BigInt.

## Разберём пример

Студент A совместим с X и Y, B только с X. Жадный выбор A—X даёт одну пару. Увеличивающий путь B—X—A—Y меняет её на B—X и A—Y: две пары. В потоке ту же возможность переназначения обеспечивают обратные дуги.

## Где ошибаются

Обратная дуга получает отправленный поток, а не исходную ёмкость. Не объединяйте независимые встречные дуги по одному индексу. Суммарный поток может превышать 32-битный диапазон; выберите точный тип с достаточным запасом.

## Практика

- 45. Распределение наставников: Дан двудольный граф: n студентов и m наставников. Каждое разрешённое ребро означает совместимую пару. Один участник может входить не более чем в одну выбранную пару. Выведите максимальное количество пар.
- 46. Пропускная способность: Найдите максимальный поток из вершины 1 в вершину n в ориентированной сети. У каждой дуги задана неотрицательная целая пропускная способность. Параллельные и встречные дуги независимы.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
