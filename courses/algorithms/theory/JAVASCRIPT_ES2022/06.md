# Монотонный стек и дек

## Что вы научитесь делать

Удалять доминируемых кандидатов; понимать амортизированное время.

Предпосылки: Предыдущие модули, 01–05.

## Идея и алгоритм

Стек хранит элементы по принципу «последний пришёл — первый ушёл», очередь — в порядке поступления, дек позволяет работать с обоими концами. В монотонной структуре дополнительно поддерживается порядок значений. Главное — не сам порядок, а доказательство, что удалённый кандидат никогда больше не улучшит ответ.

Ищем ближайший строго меньший справа. Идём справа налево. Пока вершина стека не меньше текущего значения, удаляем её: текущий элемент находится ближе ко всем будущим позициям слева и не больше удалённого. Если стек не пуст, его вершина — ближайший подходящий индекс. Затем кладём текущий индекс. Индексы нужны для ответа, а значения — для сравнения.

Для минимума в окне идём слева направо и храним дек кандидатов. Спереди убираем индексы, уже вышедшие из окна. Сзади удаляем значения, не меньшие нового: новый элемент не хуже и останется в окне дольше. После добавления нового минимум находится спереди. На первых k−1 шагах полное окно ещё не сформировалось.

Равенство обрабатывается в зависимости от задачи. Для строго меньшего справа равные значения нужно удалить. Для минимума окна можно сохранять равные, но удаление старого равного экономит память и сохраняет ответ. Если требовался самый левый индекс минимума, правило равенства пришлось бы изменить.

Амортизированный анализ считает жизнь одного элемента: он один раз добавляется и не более одного раза удаляется с каждого возможного конца. Суммарно операций O(n), даже если отдельный шаг очищает почти всю структуру. При чтении потоком минимум окна требует O(k) памяти; для ближайшего меньшего справа обычно хранится весь вход и массив ответов.

## Реализация на JavaScript

Для очереди используйте массив и индекс головы. Не вызывайте `shift()` на каждом шаге: это может потребовать сдвигов. Для памяти O(k) в скользящем окне используйте кольцевой буфер, а не растущий до n массив.

## Разберём пример

Для [4,2,2,1] ближайшие меньшие справа имеют индексы [2,4,4,−1]. Вторая двойка не является ответом для первой: сравнение строгое. Минимумы окон длины 2 того же массива: [2,2,1].

## Где ошибаются

В деке хранятся индексы или пары индекс/значение. Устаревание при текущем нулевом i — index≤i−k. Обычный стек не умеет удалять устаревшие элементы спереди.

## Практика

- 11. Ближайший спад: Для каждой позиции найдите индекс первого строго меньшего элемента справа. Если его нет, ответ −1. Печатайте n ответов, каждый в отдельной строке.
- 12. Минимум в движении: Для каждого непрерывного окна длины k выведите минимальный элемент. Окна рассматриваются слева направо, каждый ответ с новой строки.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
