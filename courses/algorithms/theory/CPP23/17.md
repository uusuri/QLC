# Дополнение: Фенвик и офлайн-запросы

## Что вы научитесь делать

Поддерживать динамические префиксы; менять порядок запросов без изменения порядка ответов.

Предпосылки: Предыдущие модули, 01–16.

## Идея и алгоритм

Теперь изменения и запросы чередуются. Пересчитывать все префиксы после каждой правки дорого. Дерево Фенвика хранит в t[i] сумму блока длины lowbit(i), заканчивающегося в i. lowbit(i)=i&−i для положительного индекса. Используется индексация с 1: индекс 0 в цикле обновления никогда не сдвинется.

Сумма префикса получается переходами i−=lowbit(i). Они разбивают [1,i] на непересекающиеся блоки. При прибавлении в позицию i переходы i+=lowbit(i) посещают все блоки, содержащие эту позицию. Оба цикла имеют O(log n) шагов. Сумма [l,r] снова является разностью двух префиксов. Присваивание превращается в прибавление разницы между новым и старым значениями.

Дерево можно собрать n обновлениями за O(n log n) или линейно, передавая вклад i в i+lowbit(i). В первом упражнении обновления именно прибавляют величину. При смене интерфейса на присваивания прежняя реализация без учёта старого значения будет неверна.

Офлайн означает, что все запросы известны заранее и их разрешено обработать в другом порядке. Для числа различных значений на [l,r] отсортируйте запросы по r. Продвигайте правую границу массива, оставляя единицу только в последнем вхождении каждого значения: предыдущую единицу убирайте. Количество единиц в [l,r] равно числу разных значений.

Чтобы вернуть ответы в исходном порядке, каждому запросу нужен ID. Онлайн-алгоритм, где ответ влияет на следующий запрос, так переставлять нельзя. Отличайте перестановку запросов от перестановки массива: значения массива остаются на исходных позициях. Этот принцип — изменять порядок обработки ради простого инварианта — встречается в сканирующей прямой, офлайн-связности и алгоритме Мо.

## Реализация на C++

В обновлении Фенвика начинайте с индекса 1. Для индекса 0 младший установленный бит равен нулю, и цикл не продвинется.

## Разберём пример

Массив [2,1,2,3]. При правом конце r=3 единицы стоят в позициях 2 и 3. Запрос [1,3] даёт 2 разных значения, [3,3] — 1. При r=4 добавится единица в позицию 4.

## Где ошибаются

Не вызывайте add(0,…). Удаляйте старое вхождение перед установкой нового. Не печатайте ответы в порядке сортировки запросов.

## Практика

- 33. Живые измерения: Поддерживайте массив. Операция + i x прибавляет x к a[i], операция ? l r требует сумму включённого отрезка. Каждый ответ выведите отдельно.
- 34. Разнообразие на отрезке: В неизменяемом массиве для каждого запроса l r найдите число различных значений на отрезке включительно. Выводите ответы в исходном порядке запросов.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
