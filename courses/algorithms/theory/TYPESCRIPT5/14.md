# DSU и минимальный остов

## Что вы научитесь делать

Поддерживать слияния компонент и применять свойство разреза.

Предпосылки: Предыдущие модули, 01–13.

## Идея и алгоритм

Система непересекающихся множеств, DSU, хранит разбиение элементов на группы. find(x) возвращает представителя группы, union(a,b) объединяет две группы. В графе, где рёбра только добавляются, группы совпадают с компонентами связности. Хранить все пути или повторно запускать BFS для каждого запроса не нужно.

Внутри DSU используется лес родительских указателей. Сжатие путей при find переводит посещённые вершины ближе к корню. Объединение по размеру подвешивает меньший корень к большему. Вместе эти эвристики дают O(α(n)) амортизированного времени на операцию, практически постоянного, но математически не просто O(1). Родитель p[x] не обязательно равен корню: сравнивайте find, а не непосредственные указатели.

DSU в этом виде не поддерживает удаление рёбер. Удаление может разделить компоненту, а структура уже потеряла сведения о том, какие рёбра обеспечивали связь. Для офлайн-удалений возможна обратная обработка, для более сложной динамики — откаты и другие методы. Не обещайте интерфейс, которого структура не обеспечивает.

Остовное дерево соединяет все вершины без циклов и содержит n−1 ребро. Алгоритм Краскала сортирует рёбра по весу и берёт ребро, если его концы пока в разных компонентах DSU. Петли автоматически отвергаются; кратные рёбра и отрицательные веса допустимы. Вес ответа суммируется в number или bigint.

Обоснование опирается на свойство разреза: минимальное ребро, соединяющее две стороны подходящего разреза, можно включить в некоторый минимальный остов. Если выбранных рёбер меньше n−1, граф несвязен: алгоритм построил минимальный лес, но задача требует сообщить об отсутствии остова. Для одной вершины пустое дерево корректно и стоит 0. Альтернатива — алгоритм Прима; на плотном графе его реализация O(n²) может быть уместнее сортировки всех рёбер.

## Реализация на TypeScript

Родителя и размер компоненты храните в целочисленных массивах. Вес остова суммируйте в подходящем широком типе. Для `number[]` используйте `a.sort((x, y) => x - y)`: наличие типов не делает стандартную сортировку числовой по умолчанию. Для `bigint[]` верните из компаратора −1, 0 или 1 типа `number`. Конкретную асимптотику встроенного `sort` задаёт реализация среды, а не система типов.

## Разберём пример

Рёбра 1—2 (4), 2—3 (1), 1—3 (2): Краскал сначала берёт 2—3, затем 1—3; ребро веса 4 замкнуло бы цикл. Вес остова 3. Отрицательное ребро тоже обрабатывалось бы по порядку веса.

## Где ошибаются

Объединяйте корни, а не произвольные вершины. Не считайте повторное объединение успехом. Проверяйте число выбранных рёбер в конце.

## Практика

- 27. Растущая сеть: Изначально n вершин изолированы. Операция + u v добавляет неориентированное ребро. Операция ? u v спрашивает, соединены ли вершины путём. Для каждого запроса выведите YES или NO.
- 28. Цена общей сети: В неориентированном взвешенном графе найдите вес минимального остовного дерева. Если связать все вершины невозможно, выведите DISCONNECTED. Для одной вершины стоимость 0.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
