# Кратчайшие пути и отрицательные веса

## Что вы научитесь делать

Различать BFS, Дейкстру, Беллмана—Форда и Флойда; безопасно работать с бесконечностью.

Предпосылки: Предыдущие модули, 01–12.

## Идея и алгоритм

Расстояние теперь равно сумме весов, а не числу рёбер. Если все веса одинаковы, достаточно BFS. При неотрицательных весах от одного источника подходит Дейкстра. При отрицательных весах его жадное окончательное закрепление расстояния уже не обосновано. Не выбирайте алгоритм только по знакомому названию: определите число источников, плотность графа и ограничения на веса.

Релаксация дуги u→v проверяет, улучшает ли путь через u значение d[v]: если d[u]+w<d[v], сохраните меньшую сумму. В Дейкстре следующей берётся вершина с минимальной текущей меткой. В очереди с приоритетом удобно разрешить несколько записей одной вершины. При извлечении сравните записанное расстояние с актуальным d[u] и пропустите устаревшую запись. Добавляйте только строгое улучшение, иначе нулевые циклы могут создавать лишнюю работу.

Беллман—Форд последовательно релаксирует все рёбра. После i полных проходов известны оптимальные стоимости путей не более чем из i рёбер, если читать предыдущий слой; обычное обновление на месте может распространить улучшения быстрее. Без достижимых отрицательных циклов достаточно n−1 прохода. Улучшение на следующем проходе свидетельствует о достижимом отрицательном цикле. Недостижимый компонент не должен влиять на ответ источника.

Для множества запросов на небольшом графе используйте Флойда—Уоршелла. d[i][j] хранит лучший путь с промежуточными вершинами из уже разрешённого набора. Цикл по новой разрешённой вершине k — внешний. Переход через k складывает два достижимых расстояния. На диагонали изначально 0; для кратных рёбер берётся минимум. В задаче курса отрицательные циклы исключены.

INF — специальное состояние, а не обычное большое расстояние. Не складывайте его с отрицательным весом. Возьмите значение с запасом относительно максимального конечного пути и храните суммы в number или bigint. В дереве отрицательное ребро не мешает вычислять единственный простой путь; в общем неориентированном графе возможность многократного обхода такого ребра меняет постановку кратчайшего маршрута.

## Реализация на TypeScript

В стандартной библиотеке нет очереди с приоритетом. Напишите кучу на `number[]` или типизированном массиве записей с функцией сравнения. Типы помогают описать элемент, но вставку и просеивание всё равно нужно реализовать. Проверяйте устаревшую запись по сохранённому расстоянию, прежде чем просматривать рёбра.

## Разберём пример

Дуги 1→2 вес 5, 1→3 вес 1, 3→2 вес 1 дают d[2]=2, хотя прямое ребро весит 5. В очереди может остаться устаревшая запись (5,2); её нужно пропустить после извлечения.

## Где ошибаются

Не запускайте обычную Дейкстру с отрицательными рёбрами. Не заменяйте минимум последним кратным ребром. Не переставляйте внешний цикл k у Флойда.

## Практика

- 25. Доставка с тарифами: Найдите кратчайшие расстояния от s до всех вершин ориентированного графа с неотрицательными весами. Для недостижимых выведите −1. Ответы для вершин 1…n, по одному в строке.
- 26. Таблица маршрутов: Найдите расстояния для заданных пар вершин ориентированного графа. Веса могут быть отрицательными; отрицательных циклов во входе нет. Для недостижимой пары выведите INF, иначе целое расстояние.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
