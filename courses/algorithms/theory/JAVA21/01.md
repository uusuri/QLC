# От работающего к эффективному

Возьмём массив `[2, 4, 4, 7, 9, 1]`. Нужно найти самый длинный участок, на котором каждое следующее число больше предыдущего. Пропускать элементы нельзя: они должны идти подряд. Здесь подходит `[4, 7, 9]`, поэтому ответ — 3.

Задачу можно решить несколькими способами. Разберём два из них: оба дают правильный ответ, но на большом массиве разница в скорости окажется огромной.

## Первое решение: проверить каждое начало

Начнём с первого элемента и пойдём вправо, пока числа растут. Запомним длину участка. Затем сделаем то же самое со второго элемента, с третьего — и так до конца массива.

Пусть в массиве n элементов, n ≥ 1:

```java
int best = 1;
for (int start = 0; start < n; ++start) {
    int length = 1;
    while (start + length < n && a[start + length] > a[start + length - 1]) {
        ++length;
    }
    best = Math.max(best, length);
}
```

Так мы переберём все возможные начала и найдём нужный участок. На шести числах решение вполне удобное. А если чисел 200 000?

Особенно много работы будет, когда **весь массив возрастает**. С первого элемента придётся дойти до конца, со второго — снова до конца. Одни и те же числа программа будет просматривать много раз.

Сравнений соседних элементов получится:

`(n − 1) + (n − 2) + … + 1 = n(n − 1) / 2`.

Для 200 000 элементов это почти 20 миллиардов сравнений. Правильность решения от этого не страдает, но уложиться в небольшой лимит времени будет трудно.

## Что мы пересчитываем зря

В участке `[4, 7, 9]` сначала проверяются пары 4 и 7, затем 7 и 9. Когда перебор начнётся с 7, пара 7 и 9 будет проверена ещё раз. Избавимся от повторных проверок.

Достаточно идти по массиву слева направо и помнить длину участка, который заканчивается на текущем элементе. Если следующее число больше, увеличиваем длину на один. Если меньше или равно — начинаем новый участок длины 1.

Отдельно храним наибольшую длину, которую встретили. Она может относиться к участку, который уже закончился.

| Прочитали число | Длина текущего участка | Лучшая длина |
| ---: | ---: | ---: |
| 2 | 1 | 1 |
| 4 | 2 | 2 |
| 4 | 1 | 2 |
| 7 | 2 | 2 |
| 9 | 3 | 3 |
| 1 | 1 | 3 |

Две соседние четвёрки не образуют возрастающую пару. Поэтому на второй четвёрке текущая длина сбрасывается, а лучший ответ сохраняется.

```java
int current = 1;
int best = 1;
for (int i = 1; i < n; ++i) {
    if (a[i] > a[i - 1]) {
        ++current;
    } else {
        current = 1;
    }
    best = Math.max(best, current);
}
```

Теперь каждая соседняя пара сравнивается ровно один раз. Всего n − 1 сравнений, даже если весь массив возрастает.

## Как сравнивать такие решения

Посчитаем сравнения на полностью возрастающем массиве:

| Чисел в массиве | Проверяем каждое начало | Делаем один проход |
| ---: | ---: | ---: |
| 10 | 45 | 9 |
| 1 000 | 499 500 | 999 |
| 200 000 | 19 999 900 000 | 199 999 |

При увеличении n вдвое первое решение делает примерно вчетверо больше сравнений. Это **квадратичная сложность**, O(n²). У второго число сравнений увеличивается примерно вдвое: **линейная сложность**, O(n).

Почему мы записали n² вместо n(n − 1)/2? Для сравнения алгоритмов обычно достаточно понять, как быстро растёт число действий. Деление на 2 и вычитание n не меняют того, что при больших n в формуле главную роль играет квадрат.

Такое описание роста называют **асимптотической оценкой**. Буква O задаёт верхнюю границу: например, O(n) означает, что при достаточно больших n число действий не превышает C·n с некоторой постоянной C. Более точное обозначение Θ понадобится нам в следующем уроке, при выборе ответа в тестах.

Мы считали сравнения, но в программе есть ещё прибавления, присваивания и проверки границ. В этих двух решениях на одно повторение цикла приходится постоянное число таких действий, поэтому оценки останутся теми же.

**Сложность не сообщает точное время в секундах.** Оно зависит от компьютера и реализации. Оценка нужна раньше замеров: по ней видно, что стоит пробовать на 200 000 элементах, а что лучше сразу переделать.

## Почему мы выбрали возрастающий массив

На убывающем массиве внутренний цикл первого решения будет останавливаться сразу. Такой тест не покажет проблему со скоростью.

Программа должна успевать на любых данных из условия. Поэтому обычно оценивают **худший случай** — здесь это полностью возрастающий массив. Ранний выход из цикла полезен, но нужно проверить, что произойдёт, если выйти рано не получится.

## Куда уходит память

Во втором решении есть массив a и три переменные: current, best и i. Массив занимает O(n) памяти, а число переменных не зависит от n.

| Что считаем | Память |
| --- | --- |
| Уже переданный в функцию массив | O(n) |
| Дополнительно к массиву: длины и счётчик | O(1) |
| Всё вместе | O(n) |

O(1) читается «о от единицы» и означает постоянный объём. Это не обязательно одна ячейка: десять переменных тоже дают O(1).

Для нашей задачи весь массив можно вообще не сохранять. Чтобы сравнить соседние числа, достаточно помнить предыдущее. Тогда программа будет читать числа по одному и использовать O(1) памяти.

В рекурсивной программе память нужна ещё и для незавершённых вызовов. Если таких вызовов n и каждый хранит несколько чисел, стек занимает O(n). В следующем уроке разберём это на примере.

## Теперь попробуйте сами

В практике две задачи. «Контрольная сумма» — короткая разминка на один проход. В «Полосе роста» нужно реализовать разобранное решение.

Перед отправкой проверьте массив из одного числа, равные соседние числа и участок, который заканчивается на последнем элементе.

Сумма 200 000 чисел по 10⁹ равна 2·10¹⁴: для неё нужен `long`, а не `int`. При умножении двух `int` пишите `(long) a * b`: приведение должно произойти до умножения. Запись `long result = a * b` сначала выполняет умножение в `int` и может дать неверный результат.

После задач переходите к «Считаем сложность кода». А в «Доказательствах» разберём, почему оба решения выше находят верный ответ.
