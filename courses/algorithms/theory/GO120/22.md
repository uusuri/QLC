# Дополнение: Ахо—Корасик и суффиксный автомат

## Что вы научитесь делать

Искать много образцов за один проход; считать разные подстроки без их перечисления.

Предпосылки: Предыдущие модули, 01–21.

## Идея и алгоритм

Когда образцов много, независимый КМП для каждого повторно читает текст. Бор объединяет общие префиксы образцов: путь от корня задаёт строку, конечная вершина отмечает образец. Одинаковые образцы могут иметь одну конечную вершину, но сохраняют отдельные ID ответа.

Ахо—Корасик добавляет суффиксные ссылки: из вершины они ведут в вершину самого длинного собственного суффикса её строки, присутствующего в боре. BFS по глубине строит ссылки, поскольку необходимые более короткие состояния уже готовы. Для фиксированного алфавита можно заполнить все переходы: отсутствующий переход наследуется от суффиксной ссылки.

После чтения каждого символа текста увеличьте счётчик посещённого состояния. Образец может совпасть не только в текущей вершине, но и по цепочке ссылок. Вместо обхода всей цепочки каждый раз передайте счётчики родителям по суффиксным ссылкам в обратном BFS-порядке. Это даёт линейное накопление. Плотные 26 переходов на вершину требуют O(26P) памяти; здесь алфавит специально ограничен.

Суффиксный автомат решает другую задачу: компактно представляет все подстроки одной строки. Состояние объединяет подстроки с одинаковым множеством позиций окончания. В нём хранится len — максимальная длина, переходы и suffix link. Все длины одного состояния лежат между len(link)+1 и len. Поэтому число различных непустых подстрок равно сумме len[v]−len[link[v]] по состояниям, кроме корня.

При добавлении символа создаётся новое конечное состояние. Недостающие переходы ставятся по цепочке ссылок. Если встретившийся переход ведёт в q и len[p]+1 не равен len[q], требуется клон q с укороченным len; часть переходов перенаправляется в клон, ссылки q и нового состояния меняются. Это самая тонкая часть: клон копирует переходы и ссылку, но не представляет новое отдельное вхождение. Число состояний не превышает 2n−1 для n≥2. Начните с ручного разбора ababa и abb, затем проверьте реализацию перебором всех подстрок коротких строк.

## Реализация на Go

`s[i]` возвращает байт. Для латинского алфавита это удобно; для Unicode сначала получите `[]rune` и учитывайте дополнительную память. Для узлов подходит срез структур, а дети могут храниться как индексы. После `append` срез может ссылаться на новый массив: старый указатель остаётся допустимым, но может указывать уже не на элемент нового среза.

## Разберём пример

Образцы a, ba и aba в тексте aba: a встречается дважды, ba один раз, aba один раз. После полного aba нужно учесть совпадения по суффиксным ссылкам. Различные подстроки aba: a,b,ab,ba,aba — всего 5.

## Где ошибаются

В Ахо не забывайте накопление по ссылкам и повторяющиеся образцы. В автомате ответ может быть порядка n², нужен int64. Обычный бор всех подстрок квадратичен.

## Практика

- 43. Поиск по словарю: Для каждого образца посчитайте число его вхождений в общий текст. Перекрытия учитываются. Одинаковые образцы во входе требуют отдельных одинаковых ответов. Ответы в порядке образцов, по одному в строке.
- 44. Словарь подстрок: Найдите количество различных непустых подстрок строки. Одинаковые подстроки, встречающиеся в разных местах, учитываются один раз.

Решайте задачи по порядку. Если застряли, сначала сформулируйте медленный корректный способ, затем откройте одну подсказку. После решения объясните оценку времени и памяти и придумайте контрпример к своей первой неверной идее. Доказательства вынесены в следующий необязательный урок; для перехода дальше читать их не требуется.
